Runs on Forgejo

Forgejo is that codebase. It's what Codeberg.org itself runs on. Why Forgejo specifically? 1. It was built for exactly this job It's a single binary / single Docker container that gives you 90% of what GitHub does for managing repos — without something as heavyweight as GitLab. Web UI, pull requests, issues, releases, packages, wiki, Forgejo Actions (GitHub Actions-compatible). 2. Lightweight Genuinely lighter-weight (∼100 MB vs. GitLab CE's ∼2–3 GB steady-state) and a reasonable choice on resource grounds alone. You can run a full platform on a $5 VPS. GitLab CE needs a server. 3. It's the community fork of Gitea Forgejo started as a soft fork of Gitea in late 2022, now a hard fork. Why the fork? • Gitea is controlled by a for-profit company (Gitea Ltd.). It requires copyright assignment, hosts its own development on GitHub using GitHub Actions and Crowdin - all proprietary platforms. • Forgejo is maintained by Codeberg e.V., a non-profit. It is developed in the open, using free tools: Forgejo to host code, Forgejo Actions for CI, Weblate for translations. If you build a platform on Gitea, you're dependent on a single commercial vendor's roadmap. That's why the Netherlands government chose Forgejo over Gitea for code.overheid.nl - digital sovereignty and jurisdictional control, nonprofit governance and AGPL licensing align with avoiding vendor dependence. 4. No lock-in philosophy Forgejo's stated objective is to "liberate software development from the shackles of proprietary tools". It's AGPL, same lightweight footprint as Gitea, governance not tied to a single company.

  • Why we put Codegen in Codeberg?

    It's a values vs. network-effects choice. GitHub is where everyone is. Codeberg is where your code isn't a product. Here's why people move: 1. It's non-profit, EU-hosted, and not Microsoft Codeberg e.V. is a registered non-profit in Berlin. It's run by its members, not shareholders. That matters if you don't want your infrastructure owned by Microsoft. 2. No AI training on your code This is the big one in 2025-2026. Codeberg's privacy policy explicitly says they will not use your code for model training, and in July 2026 they voted to restrict LLM-generated projects. GitHub does the opposite — your public code powers Copilot, which they resell. 3. The platform itself is open source GitHub is proprietary. Codeberg runs on Forgejo (a fork of Gitea), which is fully open source. You can inspect it, contribute to it, or self-host the exact same stack with zero lock-in. 4. Privacy and tracking Codeberg claims your code remains free and secure and they won't track or sell your data. No ads, no trackers, no "social coding" algorithmic feed. 5. Lightweight and community-driven It's built on Gitea, so it's extremely lightweight compared to GitHub/GitLab. And as a community-driven org, it prioritizes user values over commercial interests. When you should NOT use Codeberg: Audience: GitHub has 100M+ monthly active users, Codeberg ∼300k. If you want contributors, stars, and hiring visibility, GitHub wins. CI/CD & Integrations: GitHub Actions + 20k marketplace actions is unmatched. Codeberg's Woodpecker CI is fine, but slower and smaller. Proprietary work: Codeberg themselves say they don't want to host proprietary/commercial closed-source projects — they are for FOSS. For a company, the realistic alternative is self-hosted Forgejo or accepting GitHub. Most people who care do both: develop on Codeberg as primary, and mirror to GitHub for reach with git remote add codeberg + git remote add github.
